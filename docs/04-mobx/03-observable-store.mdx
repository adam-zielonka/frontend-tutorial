Move the previous counter's value and operations into `CounterStore`. `makeAutoObservable` infers observable fields and actions; `autoBind` keeps methods attached to their instance when passed as callbacks. `add` must accumulate its argument, rather than replace the value.

**Setup from step 2:** `/Store.ts` is new. `App` creates one store with a lazy `useState` initializer and passes it to `Counter`. For this step only, the supporting component copies `counter.value` into React state after each action. This explicit bridge keeps the preview interactive while you focus on the store. It is removed in step 4, where React will subscribe through `observer`.

## Why introduce a store?

Local state worked for one component. A model gives the value and the operations that change it one home, so other components and tests can use the same rules. A class is a blueprint for those objects: `new CounterStore()` creates one instance, its constructor prepares it, and `this.value` refers to that instance's value. Two instances can hold different values.

Here `observable` means MobX can track reads and changes; an `action` is an operation that changes observable state. `makeAutoObservable` connects ordinary fields and methods to that machinery. It does not draw anything on screen by itself. The second argument allows overrides (none are needed yet); the third enables `autoBind`, so passing `counter.reset` as a callback does not lose which counter `this` refers to.

The supplied `useState(() => new CounterStore())` retains the model object for this mounted app. It is not the temporary copy of the numeric value inside `Counter`; that separate bridge exists only for this lesson.

Validate numbers before assignment: a bad delta or arithmetic overflow must leave the previous value intact.


## Walk through the change

1. In `/Store.ts`, keep the existing import and value field, and complete the constructor:

   ```ts
   constructor() {
     makeAutoObservable(this, {}, { autoBind: true });
   }
   ```

   MobX infers the field as observable and methods as actions; binding lets a method retain `this` when used as a callback. See [observable state](https://mobx.js.org/observable-state.html).
2. Replace the body of the supplied `add` method so it calculates a possible next value before assigning it:

   ```ts
   add(delta: number) {
     const next = this.value + delta;
     if (Number.isFinite(delta) && Number.isFinite(next)) this.value = next;
   }
   ```

   `delta` is the change, not the desired final value: from 100, adding -1 produces 99. Rejecting a non-finite input or result keeps a bad value out of the model.

3. In `reset`, assign `this.value = 0;`. This is a model operation independent of React. Addition must accumulate: assigning `delta` itself would replace the old value. Checking the result also rejects overflow.

The supplied bridge copies the model value into React state after each action. Once completed, +100 then -1 shows 99 and Reset shows 0. If clicks do nothing, check that both the constructor and methods have been filled in.

If the preview still behaves like the starter after those edits, use **Refresh preview** to recreate the model with your updated constructor and methods. Hot updates can keep an instance created from the earlier code; refreshing the running example does not clear your editor draft.
