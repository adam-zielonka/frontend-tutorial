Continue in the local project from [4.13](./13-edit-value.mdx). The original chapter exposes a singleton store in the browser console. Our app owns its store inside `App`; a debugger can inspect that instance without changing ownership.

## Inspect an action

In browser developer tools, open `src/Store.ts` and put a breakpoint inside `add` or `setValue`. While paused, `this` is the counter instance; inspect `this.value` and the call stack to connect the UI event to the model action.

For an optional comparison with the original **singleton** pattern, export one shared instance at the bottom of `src/Store.ts` and explicitly type its temporary browser exposure:

```ts title="/Store.ts"
export const store = new Store();
declare global {
  interface Window { store: Store }
}
window.store = store;
```

In `src/App.tsx`, replace the `Store` import with `store` in the existing named import, and remove `const [store] = useState(() => new Store());`. Keep `CounterStore`, `connectPersistence`, the other React state and the persistence effect. Now the app and `window.store` refer to the **same** instance. Copying only the assignment would expose an unrelated model.

Subscriptions still belong to the app effect, not the singleton's constructor. Remove the global exposure after experimenting because other page scripts can access it; restore the app-owned instance to return to the lesson design.

## Check your work

Pause one +1 click inside `add` and confirm `this.value` is the clicked counter's pre-update value. Resume to see the increment.
