**Setup from step 8:** URL serialization and validated hydration are already complete. The supplied app effect now calls the new `connectPersistence` stub, which still restores and synchronizes the URL. Add storage restoration and an `autorun` without changing the counter UI.

A valid URL wins, including `?value=` for an empty list. If the URL is absent or invalid, read `mobx-counter-values-v1` from `localStorage`. Parse a JSON array into `unknown`; accept at most four finite numbers and reject strings, objects, malformed JSON and oversized data. Reuse validated hydration only after checking that shape. Missing or unusable data leaves the initial counter in place.

Restore **before** starting either writer. Save only numeric values, rather than model instances or IDs. An `autorun` tracks those values and also writes immediately. Catch read and write failures, and return cleanup for both the storage autorun and URL reaction.

To check storage restoration in an exported app, edit counters, remove the `value` parameter from the address, and reload. A normal reload keeps the URL, so it tests URL restoration instead. Also test `[]`, invalid JSON, `["3"]`, `[1e309]`, and blocked storage. The embedded preview may isolate or restrict storage; its app data is separate from the lesson editor's saved source draft.


## Walk through the change

1. In `/Store.ts`, inside `connectPersistence` after `restoreUrl`, use `if (!restoredFromUrl)` to read `window.localStorage.getItem(STORAGE_KEY)` in `try/catch`. Before parsing, require a non-null string no longer than 1024 characters. Parse as `unknown` and check its shape:

   ```ts
   const values: unknown = JSON.parse(raw);
   if (Array.isArray(values) && values.length <= store.limit &&
       values.every(value => typeof value === 'number' && Number.isFinite(value))) {
     store.hydrate(values.join(';'));
   }
   ```

2. Keep `const stopUrl = syncUrl(store);` after restoration. Then create `const stopStorage = autorun(() => { ... });`: map counters to values, `JSON.stringify` that array, and call `window.localStorage.setItem(STORAGE_KEY, snapshot)` inside `try/catch`.
3. In the returned cleanup function, call both `stopUrl()` and `stopStorage()`. [Autorun](https://mobx.js.org/reactions.html) runs immediately and tracks the observable values read in its body, so restoring first avoids overwriting saved data. A valid URL, including an empty `value`, takes precedence.

In an exported app, change a counter, remove the `value` query parameter, then reload: storage should restore it. A normal reload with the parameter tests URL priority instead. Invalid JSON, non-number arrays or blocked storage leave the initial state usable. If restoration fails, inspect the storage key and URL first; the embedded preview may isolate storage ([localStorage](https://developer.mozilla.org/en-US/docs/Web/API/Window/localStorage)).
