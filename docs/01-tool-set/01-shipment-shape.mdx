Look at the three shipments in the preview. Which one needs express delivery? At the moment, the person reading the list has no way to tell. You’ll add that information to each record and show it next to the shipment.

Start in `/shipments.ts`. The TypeScript [interface](https://www.typescriptlang.org/docs/handbook/2/objects.html) named `Shipment` describes what every shipment record must contain. Give it a field called `priority`, with two possible values. Then you can fill in the records and let React display what you entered. The browser exercise is ready to edit. In a local copy, Node runs the tools and Vite serves the app.

1. In `/shipments.ts`, replace the TODO inside `Shipment` with this field:

   ```ts title="/shipments.ts"
   priority: 'standard' | 'express';
   ```

   The colon introduces a type, and `|` means either of the two string values is allowed. The field is required, so every `Shipment` must supply it. The interface describes data; it does not create a priority value by itself.
2. In the array below, add `priority: 'express'` to S-101 and `priority: 'standard'` to each other object. Commas separate object properties. Until all three are updated, a type checker can report missing fields.
3. In `/App.tsx`, replace the TODO inside the list item with:

   ```tsx title="/App.tsx"
   <span> · {shipment.priority}</span>
   ```

   The existing `shipments.map(...)` renders one list item per record. Within that item, `shipment` names the current record. JSX braces read its priority instead of displaying the literal words `shipment.priority`.

If a value is rejected, check its spelling and quotes against the union; `Standard` is a different string. In a local export these editor files live under `src/`.
