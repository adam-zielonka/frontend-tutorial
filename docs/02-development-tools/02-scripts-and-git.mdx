The starter carries forward the two enabled checklist values. The strings in `/project.ts` describe commands for practice; they do not run them. A real terminal and the exported project's `package.json` are separate.

1. In `/project.ts`, find `scripts` in `project` and set `dev: 'vite --host 0.0.0.0'` and `typecheck: 'tsc --noEmit'`. The preview compares exact strings and should show 4 / 4 ready. `--host` listens on all addresses; use it only when network access is intended ([Vite server options](https://vite.dev/config/server-options)).
2. In a terminal in the exported project, run `pnpm install`, then `pnpm exec tsc --noEmit` and `pnpm dev`. Open the printed local address; Ctrl+C stops Vite. To run `pnpm typecheck` instead, add `"typecheck": "tsc --noEmit"` to the actual `scripts` object in `package.json`, with a comma between entries.
3. In your own new project folder, run `git init`, `git status`, and `git diff`. Stage reviewed source files with `git add <paths>` and commit with `git commit -m "Initial checkpoint"`. Git records staged changes; check `.gitignore` and exclude dependencies and secrets. See [Git's guide](https://git-scm.com/book/en/v2/Git-Basics-Recording-Changes-to-the-Repository).

If the model remains at 2 / 4, compare spaces and spelling in the strings. If a real command is missing, check the terminal's current folder and installed tools. Browser DevTools Console and Network help inspect errors and requests.
