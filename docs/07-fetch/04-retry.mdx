A retry must start a new request rather than just dismissing the old error. Store a request counter, increment it on Retry request, and include it in the effect dependency array alongside the URL.

The same effect now handles first load, URL changes, and retries: it clears the old error, shows loading, and finishes with data or an error. Cleanup cancels the preceding request. Repeating the missing path should fail again; restore the working fixture and retry to return to the three ramps.

The fixture is intentionally fast. Use browser Network tools if you want to inspect repeated requests and the brief loading state. This remains local fixture practice; production API routing, authentication, and cross-origin policy need their own configuration.
