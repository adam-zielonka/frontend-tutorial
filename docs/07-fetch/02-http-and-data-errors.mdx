A completed request is not necessarily a successful response. Check `response.ok` before parsing and include the HTTP status in the error. JSON parsing can fail separately, and valid JSON can still have the wrong structure.

Read the parsed value as `unknown`. Require an array, then check every element is a non-null object containing string `id` and `name` fields. Only then return it as `Ramp[]`. The existing catch handler displays these failures instead of treating them as an empty successful result.

The missing-fixture checkbox exercises the error path. A development server can return an HTML fallback with status 200 for an unknown path, so the displayed error may be a JSON parsing error rather than HTTP 404. To exercise the data guard, temporarily give a fixture record a numeric name, then restore it. The supplied path adapter can make a second request for the working fixture; it is compatibility scaffolding, not a retry button.
