A completed request can carry an unsuccessful HTTP response. `fetch` rejects for failures such as network errors, but a status like 404 or 503 still resolves to a `Response`. Check its status before treating the body as data.

## Edit the status guard

In `/api.ts`, insert the highlighted line between the existing request and JSON parse:

```ts title="/api.ts" {2}
const response = await fetch(url, { signal });
if (!response.ok) throw new Error(`HTTP ${response.status}: could not load ramps`);
return await response.json() as Ramp[];
```

The effect's existing catch handler displays the error. Do not turn it into an empty successful array: an empty result and a failed request communicate different things.

The missing-fixture checkbox explores failure, but development servers sometimes return HTML with status 200 for an unknown path. That produces a JSON parse error rather than HTTP 404. The following controlled check isolates HTTP handling from that server behavior.
