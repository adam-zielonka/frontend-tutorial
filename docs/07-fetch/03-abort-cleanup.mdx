Changing the URL starts another effect. The previous request may finish later, so its result must not replace the newest selection. The supplied `active` flag already guards state updates; now also cancel obsolete work.

Create one `AbortController` per effect setup, pass its signal to the adapter, then mark the effect inactive **before** aborting in cleanup. This order keeps intentional cancellation out of the error UI. The adapter already avoids its fallback when the signal is aborted.

Rapidly toggle the fixture option and confirm the final selection determines the displayed state. A tiny local file can resolve too quickly to reveal a race, so use Network throttling in browser developer tools if needed. React Strict Mode also runs an extra setup/cleanup cycle during development, which this cleanup must tolerate.


## Worked walkthrough

1. In `/App.tsx`, inside the effect before `loadLocalRamps`, create `const controller = new AbortController();` and pass `controller.signal` as its second argument.
2. Replace cleanup with `return () => { active = false; controller.abort(); };`. React calls cleanup before replacing an effect; marking it inactive first prevents intentional cancellation from appearing as an error. The adapter already avoids fallback after abort.

The existing effect contains the success/error handlers. Keep those handlers and their `if (active)` checks. Replace the request line with:

```ts
const controller = new AbortController();
loadLocalRamps(url, controller.signal).then(data => {
```

The second line opens the existing success callback: retain its body, closing braces and `.catch(...)` below it. At the end of the effect, replace the old cleanup with:

```ts
return () => {
  active = false;
  controller.abort();
};
```

The controller requests cancellation of the fetch operation. The flag protects React state even if a completion has already been queued. A controller belongs to one effect run: creating it outside the effect could reuse an already-aborted signal on the next request.

Toggle the fixture option rapidly. The final selection should determine the result. If the local request finishes too quickly to observe cancellation, use network throttling; development Strict Mode may also run an extra setup and cleanup.
